Why you're getting Error 400

The OAuth client authorizes exactly one origin: http://localhost. But your page is never actually served from localhost — it's file:// on the laptop, and some app/webview origin on the iPhone. Google's token client compares the page's real origin against your authorized list, finds no match, and returns 400: invalid_request / "doesn't comply with OAuth 2.0 policy." It's purely a configuration/hosting mismatch — the code itself is fine, and Drive API being enabled is good.

Three misconceptions to clear up before you act

  1. Origins are per-website, not per-device. You don't need "one URI for mobile, one for laptop." If the app lives at one URL, both devices use that same single origin. Drop the idea of adding a second origin "for Windows."
  2. http://localhost on the iPhone means the iPhone itself. Each device's localhost is itself — the laptop's localhost is unreachable from the iPhone. And Google only permits http:// for localhost; any other host (like your laptop's LAN IP, e.g. 192.168.x.x) must be https://, so there's no local-network workaround for the iPhone.
  3. A webview wrapper won't fix it either. If the iPhone "app" is an HTML file loaded in a webview, its origin is file:// or a custom scheme — both rejected by Google's sign-in. The page must be served from a real https:// URL.
And yes — the empty "Authorized redirect URIs" is fine. Your code uses initTokenClient() (browser flow), which only checks JavaScript origins.

        entry.payments.forEach(p => counts.set(p.amount, (counts.get(p.amount)||0)+1));
